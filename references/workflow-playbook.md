# 方法论工作手册（Workflow Playbook）

## 一、五层拆解法：参考"语言"，不复制"皮肤"

看到喜欢的页面，不要整体照搬。拆成五层，逐层为目标项目重做：

1. **构图**：首屏比例、视觉重心位置、留白节奏、信息分区与动线。
2. **节奏**：滚动速度感、分区切换的呼吸感、动画时长/缓动的整体统一性。
3. **材质**：颗粒、噪点、玻璃、纸张、渐变、模糊、纹理的质感选择。
4. **光线**：明暗关系、光源方向、发光/投影如何引导视线。
5. **交互**：每个动效的触发方式（滚动进度/hover/点击/惯性）、反馈逻辑、进入与退出方式。

记录方式：保存链接和录屏（链接比截图重要，动效必须在网页里看），并标注——我最喜欢的具体部分是什么（布局/颜色/字体/材质/动效）、动效何时触发、必须保留的感觉、可以替换的元素、PC 优先还是必须兼顾手机。

## 二、评估"漂亮但像海报"的页面

Dribbble 等概念稿常默认不可直接实现。遇到这类页面，先做交互可行性评估：

- 该效果在真实数据（长短文本、缺失图片、慢网）下是否成立？
- 动效依赖什么机制：纯 CSS、JS 动画库、Canvas 还是 WebGL？对应哪档难度？
- 滚动叙事在移动端是否降级为静态分区？降级后还成立吗？
- 是否存在可替代的更轻实现（如 Lottie 替代视频、CSS 替代 WebGL）？
- 结论：可作为气质参考 / 可局部移植机制 / 放弃并找可运行原型替代。

## 三、难度三档的落地策略

| 档位 | 定义 | 策略 |
|---|---|---|
| 🟢 易：挑选或小改 | 灵感站、CSS 小效果、图标、字体 | 直接挑选，只改配色/字号/间距等变量；复制前检查许可证与暗色模式适配 |
| 🟡 中：需要改造 | React/Tailwind 组件库、CodePen 原型 | 统一依赖与主题变量后再集成；去掉模板痕迹（改配色、字距、密度）；检查 reduced-motion 与键盘交互 |
| 🔴 高：需工程化 | GSAP 复杂时间线、Canvas/WebGL、生成艺术 | 先开试验分支做技术验证；改造成模块化、可暂停、可降级版本；设定性能预算后再进主项目 |

匹配原则：**项目技术栈决定可选来源**——无构建工具的纯静态项目不要选 React 组件源（21st.dev/React Bits/Magic UI/Aceternity 均需 React 环境）；这种项目改用 UIverse（纯 CSS）、Devsnap、Lottie、SVG。

## 四、授权与性能核查清单（上线前必过）

**授权**
- [ ] 代码：看仓库/作品页 License，社区代码不默认可商用
- [ ] 字体：确认 Web 嵌入授权与商业授权（Font Squirrel 也要逐款核对），保存授权来源
- [ ] 图标/Lottie：逐项确认许可，记录来源链接
- [ ] 第三方模型、照片、视频：保存来源与许可证

**性能**
- [ ] 动效首开预算：WebGL/粒子场景估算首帧耗时与内存；大字体文件子集化
- [ ] Google Fonts 自托管（国内访问与隐私稳定性）
- [ ] Lottie 文件体积与循环缝隙检查

**无障碍与降级**
- [ ] 所有动效提供 `prefers-reduced-motion` 静态替代
- [ ] 交互元素键盘可达、焦点可见
- [ ] 移动端降级方案已验证（复杂沉浸式效果 → 简化或静态版本）
- [ ] 每屏只有一个视觉主角；整页主视觉机制不超过 1–2 个
